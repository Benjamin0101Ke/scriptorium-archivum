INSTRUCCIONES DEL BACKEND

1. PREPARAR

Docker Desktop debe estar iniciado y el equipo debe tener .NET 10
Copiar .env.example como .env solo si no existe un archivo privado
Completar las contrasenas de PostgreSQL y pgAdmin
Los comentarios de la plantilla explican cada campo

2. INICIAR LA BASE

Abrir PowerShell en backend donde esta docker-compose.yml

docker compose -p scriptorium-archivum up -d postgres pgadmin
docker compose -p scriptorium-archivum ps
docker compose -p scriptorium-archivum exec -T postgres pg_isready -h 127.0.0.1 -U postgres -d scriptorium_archivum

El primer comando inicia PostgreSQL y pgAdmin
El segundo muestra sus estados y el tercero comprueba si la base acepta conexiones
-p selecciona la instalacion y debe conservar el nombre con que fue creada
-h indica el servidor dentro del contenedor y -U el usuario y -d la base
La comprobacion no revisa todas las tablas ni la API

pgAdmin se abre en http://localhost:5052 con su correo y contrasena del .env
Dentro de pgAdmin registrar host postgres y puerto 5432 y usuario postgres
La base es scriptorium_archivum y su clave es POSTGRES_PASSWORD
Desde Windows PostgreSQL se consulta en localhost:5433

3. INICIAR LA API

Abrir el proyecto C# de APIScriptoriumArchivum en Visual Studio
La API se ejecuta en Windows y Docker inicia PostgreSQL y pgAdmin
En una terminal situada donde esta el archivo .csproj ejecutar estos comandos
Sustituir la ruta de almacenamiento por la ruta absoluta de ese equipo

dotnet user-secrets set "ArchivoEntorno" "../.env"
dotnet user-secrets set "Storage:Ruta" "C:\ruta\scriptorium-archivum\backend\storage\trabajos"

ArchivoEntorno selecciona el archivo privado del backend
Storage:Ruta selecciona la carpeta donde guardar los PDF y anexos
Cada copia debe utilizar sus propias rutas de configuracion y almacenamiento
Seleccionar el perfil http en Visual Studio y ejecutar con F5 o Ctrl F5
Tambien se puede iniciar desde la terminal del proyecto

dotnet run --launch-profile http

Consultar http://localhost:3000/api/carreras para comprobar la respuesta
Un 404 en la raiz no significa que fallen las rutas /api
EntornoPrivado completa la cadena de appsettings.json con la clave y el puerto del .env
Program configura Npgsql y Entity Framework con esa cadena de conexion
Reiniciar la API si se cambian sus datos privados

4. CONECTAR LA INTERFAZ

Abrir PowerShell en frontend

npm ci
npm start -- --configuration integration --host 127.0.0.1 --port 4301

npm ci instala las dependencias y npm start inicia Angular
Abrir http://127.0.0.1:4301 y dejar la terminal abierta
El proxy envia /api al puerto 3000 de la API
Si se cambia el puerto en launchSettings.json ajustar tambien el proxy y reiniciar Angular
integracion/CONSUMIR-API.txt explica las rutas y la sesion

5. BASE Y ARCHIVOS

Son 34 tablas fisicas en total y todas forman parte de la base de datos
33 corresponden a las entidades y operaciones del sistema
La adicional es configuracion_correo_bitacora para las copias institucionales por correo
Tiene una sola fila con unica y destino y habilitado
El destino es el correo que recibe las copias y habilitado activa o desactiva la funcion
Las funciones y el trigger consultan estos valores directamente en PostgreSQL
Se pueden cambiar mediante SQL sin reiniciar la API para esos ajustes
No tiene un panel propio en la interfaz ni guarda claves SMTP ni mensajes
Las claves del envio siguen en el .env privado y los mensajes van a correos_eventos
Se crea deshabilitada y desactivarla no cancela mensajes que ya esten en cola
El conjunto tiene 260 campos y 64 claves foraneas y una vista
sql-init se ejecuta automaticamente al crear un volumen vacio
Una base existente requiere respaldo y aplicar solamente los SQL pendientes
No repetir la creacion de tablas ni ejecutar down -v sobre datos que se necesitan
Los PDF y anexos van a Storage:Ruta y las fotos de perfil se guardan en PostgreSQL
Las estrellas cuentan favoritos activos y no son calificaciones
El catalogo muestra trabajos despues de su publicacion por Biblioteca
Agregar datos de prueba es opcional y se realiza en una base aislada

6. CORREO

Completar SMTP_FROM y SMTP_USER con la cuenta de envio de la aplicacion
SMTP_PASSWORD contiene la contrasena de aplicacion privada del correo
Para Gmail se utiliza smtp.gmail.com y puerto 587 con SMTP_TLS=true
Cambiar SMTP_HABILITADO a true para permitir el envio
SMTP_AVISOS indica el buzon de avisos y vacio utiliza el remitente
SMTP_AVISOS_ACCESO permite activar o desactivar los avisos de acceso
Los avisos y sus intentos se registran en PostgreSQL
Enviado significa aceptado por SMTP y no confirma lectura
Con SMTP_HABILITADO=false no se envian avisos ni codigos de recuperacion

7. RESPALDO Y CIERRE

pruebas/RESPALDO.txt explica la copia de PostgreSQL y los archivos
Pausar escrituras durante ambas copias y comprobarlas en una instalacion aislada
Detener la API en Visual Studio o con Ctrl C en su terminal
Compose solo detiene o inicia PostgreSQL y pgAdmin

docker compose -p scriptorium-archivum stop
docker compose -p scriptorium-archivum start

No publicar .env ni claves ni archivos reales ni respaldos
