CONSUMIR LA API

Recomiendo iniciar con la prueba de catalogos y sesion. Las rutas de ejemplo
usan el puerto 3000 del perfil http de la API en Visual Studio
Si se cambia en Properties/launchSettings.json ajustar tambien el proxy del frontend
No es necesario crear otra API ni copiar controllers al proyecto Angular.

CONEXION DE ANGULAR CON LA API

Node.js ejecuta las herramientas de desarrollo de la interfaz
npm es el administrador de paquetes que se instala con Node.js
package.json indica las bibliotecas necesarias y los comandos del proyecto
Los comandos npm se ejecutan en la carpeta frontend, donde esta ese archivo

1. Iniciar primero el backend siguiendo backend/LEEME.txt
   Comprobar que http://127.0.0.1:3000/api/carreras devuelve las carreras
   Asi se confirma que la API responde antes de conectar la interfaz

2. Abrir frontend/proxy.conf.json
   Su configuracion actual envia /api/** a http://127.0.0.1:3000
   El proxy recibe las peticiones /api de la pagina y las reenvia a la API
   Por ejemplo, /api/carreras termina consultando el backend en el puerto 3000
   Si se cambia el puerto en launchSettings.json cambiar tambien el puerto de target en ese JSON
   Esto mantiene el proxy apuntando al puerto donde realmente escucha la API
   proxy.conf.example.json es solo una plantilla de referencia, si se necesita
   El archivo que utiliza este proyecto es frontend/proxy.conf.json

3. Abrir PowerShell en frontend y ejecutar:

   npm ci

   Descarga las bibliotecas con las versiones registradas en package-lock.json
   Prepara node_modules y reemplaza esa carpeta si ya existia
   No es necesario repetirlo cada vez que se inicia la pagina
   Se utiliza al preparar la copia o cuando cambian las dependencias del proyecto

4. Desde esa misma carpeta ejecutar:

   npm start -- --configuration integration --host 127.0.0.1 --port 4301

   Ejecuta el comando start definido en package.json
   En este proyecto es ng serve --proxy-config proxy.conf.json
   ng serve inicia el servidor de desarrollo de Angular
   --proxy-config le indica que utilice el archivo de proxy mencionado
   integration utiliza la API real y el puerto 4301 corresponde a Angular
   La terminal muestra la direccion http://127.0.0.1:4301
   Abrir la direccion que realmente aparezca y dejar esa terminal abierta
   Para detener ese servidor se utiliza Ctrl+C en su terminal

5. Si se modifica proxy.conf.json, detener Angular y ejecutar npm start otra vez
   El servidor necesita cargar la nueva configuracion del proxy
   La API puede seguir ejecutandose en Visual Studio durante ese cambio

6. Revisar en las herramientas del navegador la pestana Red o Network
   Las solicitudes deben ir a la direccion de la pagina y empezar por /api
   La interfaz utiliza /api, mientras el proxy se comunica con el puerto 3000
   Esto permite que pagina y solicitudes compartan origen y utilicen la sesion
   No cambiar las solicitudes para enviarlas directamente a otro origen

Cada integrante puede iniciar su propia copia del backend
127.0.0.1 representa el equipo donde se esta ejecutando el programa
No permite acceder a la computadora de otro integrante desde la propia

Para publicar la pagina se necesita un servidor con HTTPS que sirva la interfaz
y reenvie /api al backend bajo el mismo origen
El proxy de ng serve funciona durante el desarrollo y no se incluye como servidor
al compilar la pagina de produccion

Sesión y formatos

- POST /api/auth/login recibe { "correo": "...", "password": "..." }. La respuesta contiene id, nombre, correo, rol y establece una cookie HttpOnly. Conserva las credenciales de la misma procedencia en fetch y evita guardar el password o la cookie en el código.
- POST /api/auth/registro recibe nombres, apellidos, correo, password. Sin carrera crea Lector; con id_carrera valido crea Estudiante. Puede incluir id_plan de esa carrera y abre sesion. Si el correo ya existe, responde 409.
- GET /api/auth/me recupera la sesión y el perfil. PUT /api/auth/perfil recibe los campos que se quieran cambiar entre nombre, avatar, tema. PUT /api/auth/contrasena recibe actual, nueva y renueva la sesión en ese navegador.
- POST /api/auth/logout cierra sesión. 401 corresponde a sesión ausente o inválida, 403 a cuenta sin permiso.
- Los cuerpos normales van como JSON. Para cargar PDF, usa FormData con un campo archivo y deja que el navegador genere el Content-Type.
- Para la vista previa y descarga, procesa la respuesta exitosa como binario o abre la URL autenticada. El método de la interfaz que lee siempre response.json() requiere una operación específica para respuestas PDF.
- En errores JSON, muestra error. Puede incluir fields, duplicate, bloqueos o controles. Los IDs de ficha y ejemplar viajan como cadenas. Los IDs de los catálogos y de personas pueden ser numéricos.

Ejemplos para adaptar en el proyecto de interfaz

const response = await fetch('/api/auth/login', {
  method: 'POST',
  credentials: 'same-origin',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ correo, password })
});
if (!response.ok) {
  const error = await response.json();
  throw new Error(error.error);
}
const usuario = await response.json();

const form = new FormData();
form.append('archivo', archivoSeleccionado);
const respuesta = await fetch('/api/admin/trabajos/' + id + '/pdf', {
  method: 'POST',
  credentials: 'same-origin',
  body: form
});
if (!respuesta.ok) {
  const error = await respuesta.json();
  throw new Error(error.error);
}
const { ejemplar_id } = await respuesta.json();

RECUPERAR EL ACCESO A UNA CUENTA

Solicitar un codigo de recuperacion para el correo indicado
POST /api/auth/recuperacion/solicitar

Recibe {"correo":"..."} y responde 202 sin confirmar si la cuenta existe

Establecer una contrasena nueva con el codigo recibido
POST /api/auth/recuperacion/confirmar

Recibe correo, codigo y nueva
El codigo dura diez minutos y solo sirve una vez
La prueba completa esta en ../pruebas/PRUEBA-GUIADA.txt

COMO LEER LAS RUTAS

GET consulta informacion
POST envia datos para crear un registro o ejecutar una accion
PUT guarda los datos indicados o establece un estado, segun la ruta
PATCH cambia una parte concreta
DELETE retira el elemento indicado; en favoritos lo desactiva sin borrar la fila
{id} se reemplaza por el identificador real, por ejemplo /api/trabajos/12
No se escribe la palabra GET o POST dentro de la direccion
En Postman se selecciona el metodo y se escribe la URL en su campo
Desde Angular se utiliza fetch o el cliente HTTP con ese mismo metodo

Estrellas y favoritos

Las estrellas son favoritos activos y no una puntuacion

Metodo y ruta - Comportamiento
Ordena por cantidad de favoritos activos, titulo e ID.
GET /api/trabajos?orden=estrellas

Incluyen estrellas, un numero entero que empieza en cero.
GET /api/trabajos

GET /api/trabajos/{id}

Sesion requerida. Lista los favoritos activos y publicados elegibles de la cuenta.
GET /api/favoritos

Sesion requerida, sin cuerpo. Marca o reactiva el favorito propio.
PUT /api/favoritos/{id}

Sesion requerida, sin cuerpo. Desactiva el favorito propio sin borrar el registro.
DELETE /api/favoritos/{id}

Marcar dos veces no suma dos estrellas. Cada usuario aporta como maximo una por trabajo.
Al quitar el favorito deja de sumar y desaparece de la lista personal. Reactivarlo reutiliza
la misma pareja. Tras marcar o quitar, consultar el detalle para refrescar estrellas.
Las operaciones PUT y DELETE mantienen la respuesta {"ok": true}.

El catalogo mantiene los filtros existentes. La interfaz puede paginar su presentacion.

Tipos de trabajo

Los tipos de trabajo tienen nombre y estado activo. El catálogo administrativo acepta el tipo tipos-trabajo en sus rutas GET, POST y PUT. El cuerpo usa nombre (máximo 60 caracteres) y activa. GET /api/tipos-de-trabajo devuelve los tipos activos. Las fichas existentes conservan su tipo aunque este se desactive.

Avisos por correo y docente asignado

Las operaciones guardan su aviso en la misma transaccion que registra la accion. El envio de correo ocurre en segundo plano y su funcionamiento se explica en LEEME.txt.

- GET /api/admin/roles incluye docentes habilitados (id, nombre, correo), y cada cuenta incluye id_docente.
- PUT /api/admin/roles/{id}/docente acepta {"id_docente": 12}; null retira la asignación. Solo Administración; el destinatario debe ser Estudiante habilitado y el docente debe tener rol Docente revisor habilitado.
- GET /api/admin/roles/correos devuelve los últimos 100 avisos operativos, con destino, asunto, evento, estado, intentos y fechas; solo Administración. No devuelve códigos de recuperación ni claves SMTP.
- No se agregan permisos de publicación al docente ni se implementa un chat.

CORREOS: RUTAS DE ADMINISTRACION

Estas rutas requieren la cookie de una cuenta Administrador.
GET /api/admin/roles/correos
  Devuelve los ultimos 100 avisos: estado, ciclo, intentos y proxima ejecucion.
GET /api/admin/roles/correos/{id}/intentos
  Devuelve hasta 200 resultados del aviso, incluyendo ciclos anteriores.
POST /api/admin/roles/correos/{id}/reenviar
  Sin cuerpo. Solo acepta un aviso Fallido. Responde 202 y abre otro ciclo.
  Si el aviso esta Pendiente, Enviando, Enviado u Omitido, responde 409.
GET /api/admin/roles/correos/recuperaciones
  Devuelve resultados tecnicos, sin codigo, contrasena, cuerpo o destinatario.

Para conectar el boton Reintentar, mostrarlo solo cuando el estado sea Fallido.
Enviar el POST, mostrar que quedo pendiente y refrescar el listado.
El estado Enviado significa aceptacion por SMTP. No confirma lectura.
No se reenvia un codigo de recuperacion anterior desde este historial.

Sin sesion se recibe 401; sin permiso, 403; si no existe el aviso, 404.
No guardar contrasenas ni copiar cookies manualmente al codigo del frontend.
