RESPALDO Y RESTAURACION

1. ANTES DE COPIAR

La API se ejecuta en Visual Studio y PostgreSQL permanece en Docker
Detener la API con Detener depuracion o Ctrl C si se ejecuto desde una terminal
Cerrar tambien otras herramientas que puedan modificar datos durante la copia
No detener PostgreSQL porque pg_dump necesita conectarse a el
Detener Compose no detiene la API de Visual Studio
Los respaldos son privados y no se suben a GitHub

2. COPIAR LA BASE Y LOS DOCUMENTOS

Abrir PowerShell en backend donde esta docker-compose.yml
Elegir una carpeta nueva para cada respaldo y sustituir la ruta de ejemplo
La carpeta de trabajos debe coincidir con Storage:Ruta de la API
En esta instalacion corresponde a storage/trabajos de esta carpeta

$ErrorActionPreference = 'Stop'
$destino = 'C:\ruta\privada\respaldo-nuevo'
New-Item -ItemType Directory -Path $destino -ErrorAction Stop

docker compose -p scriptorium-archivum exec -T postgres pg_dump -U postgres -d scriptorium_archivum -Fc -f /tmp/scriptorium.dump
if ($LASTEXITCODE -ne 0) { throw 'Fallo pg_dump' }
docker compose -p scriptorium-archivum cp postgres:/tmp/scriptorium.dump "$destino/scriptorium.dump"
if ($LASTEXITCODE -ne 0) { throw 'Fallo la copia del dump' }
Copy-Item -LiteralPath './storage/trabajos' -Destination (Join-Path $destino 'trabajos') -Recurse -ErrorAction Stop

pg_dump lee la base y guarda sus objetos y datos en el archivo custom
La opcion -Fc elige ese formato y -f indica donde escribir el archivo
Compose cp copia el dump sin transformar sus bytes
Copy-Item copia los PDF y anexos que no estan dentro del dump
Las fotos guardadas en usuarios.foto_perfil quedan dentro del respaldo SQL
Si aparece un error no considerar completa la copia ni sobrescribir otra
Registrar fecha y conteos de usuarios y fichas y un inventario SHA256 de archivos
Conservar el .env privado por separado con acceso controlado

3. CLAVES DE PROTECCION

La API usa las claves de ASP.NET Core del usuario de Windows
Normalmente se encuentran en la siguiente carpeta

Join-Path $env:LOCALAPPDATA 'ASP.NET\DataProtection-Keys'

Confirmar su ubicacion en el registro de arranque de la API
Si se necesita preservar datos protegidos guardar tambien esa carpeta de forma privada
No se utiliza un volumen de claves de la API en Compose
Las claves pueden estar protegidas mediante DPAPI del usuario de Windows
Copiarlas a otro usuario o equipo no garantiza que puedan descifrarse
Una ruta de aplicacion diferente tambien puede cambiar el aislamiento de proteccion
En una restauracion aislada asumir sesiones y codigos pendientes invalidos
Volver a iniciar sesion y solicitar codigos nuevos cuando sea necesario
Nunca reemplazar las claves de la instalacion principal por las de una prueba

4. RETOMAR LA INSTALACION PRINCIPAL

Una vez terminada la copia volver a ejecutar la API desde Visual Studio
Si se inicio con dotnet run volver a ejecutar ese comando en su carpeta
No utilizar Compose para iniciar o detener la API

5. RESTAURAR EN UNA INSTALACION AISLADA

Preparar otra carpeta con una copia del proyecto y de docker-compose.yml y sql-init
Usar su propio .env con POSTGRES_PORT=5443 y PGADMIN_PORT=5060
Mantener la contrasena de esa instancia y configurar SMTP_HABILITADO=false
La carpeta de archivos de la copia debe estar vacia antes de restaurar
Abrir PowerShell donde esta el docker-compose.yml de esa copia
El nombre de proyecto siguiente crea otros contenedores y volumenes
No cambiarlo por el de la instalacion principal

docker compose -p scriptorium-restore up -d postgres pgadmin
docker compose -p scriptorium-restore exec -T postgres pg_isready -h 127.0.0.1 -U postgres -d postgres

Repetir pg_isready hasta que acepte conexiones antes de continuar
Se crea una base nueva sin ejecutar en ella los SQL de creacion
El dump ya contiene los objetos de la base respaldada

$respaldo = 'C:\ruta\privada\respaldo-nuevo'
docker compose -p scriptorium-restore exec -T postgres createdb -U postgres -T template0 -E UTF8 scriptorium_restaurada
if ($LASTEXITCODE -ne 0) { throw 'La base nueva no se pudo crear' }
docker compose -p scriptorium-restore cp "$respaldo/scriptorium.dump" postgres:/tmp/scriptorium.dump
if ($LASTEXITCODE -ne 0) { throw 'Fallo copiar el dump' }
docker compose -p scriptorium-restore exec -T postgres pg_restore -U postgres --exit-on-error --no-owner -d scriptorium_restaurada /tmp/scriptorium.dump
if ($LASTEXITCODE -ne 0) { throw 'Fallo restaurar la base' }
docker compose -p scriptorium-restore exec -T postgres psql -X -v ON_ERROR_STOP=1 -U postgres -d postgres -c "ALTER DATABASE scriptorium_restaurada SET TimeZone TO 'America/El_Salvador';"
if ($LASTEXITCODE -ne 0) { throw 'Fallo configurar la zona horaria' }
Copy-Item -LiteralPath (Join-Path $respaldo 'trabajos') -Destination './storage/trabajos' -Recurse -ErrorAction Stop

6. CONECTAR LA API DE LA COPIA

Editar solo el appsettings.Development.json del proyecto copiado
Agregar o ajustar esta seccion en su objeto principal sin quitar otras opciones

"ConnectionStrings": {
  "Scriptorium": "Host=localhost;Port=5443;Database=scriptorium_restaurada;Username=postgres"
}

No escribir la contrasena en ese archivo
El lector completa la clave y el puerto desde el .env de la copia
En el proyecto copiado abrir PowerShell y ejecutar lo siguiente
Sustituir las dos rutas por las rutas absolutas de la instalacion aislada

dotnet run --no-launch-profile -- --environment Development --urls http://localhost:3010 --ArchivoEntorno "C:\ruta\copia\.env" --Storage:Ruta "C:\ruta\copia\storage\trabajos" --Correo:Habilitado=false --RedireccionHttps=false

Los argumentos seleccionan archivo privado y almacenamiento y URL de la copia
No modifican los secretos ni la base ni el almacenamiento de la principal
La API restaurada se consulta en http://localhost:3010/api/carreras
Mantener esta terminal abierta durante la comprobacion
Ctrl C detiene solamente esa API
Con los correos desactivados no se prueba entrega ni recuperacion por correo

7. COMPROBAR LA RESTAURACION

Comparar los conteos de usuarios y fichas con el inventario del respaldo
Abrir las fichas y comprobar autores y permisos y archivos
Comparar las huellas SHA256 de PDF y anexos con el inventario inicial
Comprobar acceso permitido y denegado con las cuentas de prueba
La aceptacion de RNF-06 requiere dos copias separadas por hasta siete dias
Tambien requiere el cotejo completo de diez fichas con archivos y datos de control
Si faltan datos o alguna comprobacion registrarlo como pendiente
Un pg_restore sin errores no demuestra por si solo que se recupero todo
